FAQ

Answers, directly.

What is Jesun.Code?

Jesun.Code is a programming language that reads like plain English. show "hello" prints, ask "name?" giving n reads input, repeat 3 times loops. It ships as a single binary for Windows, macOS, and Linux, so you never install Python and never see it.

How do I install it?

One line, no Python needed. On macOS/Linux: curl -fsSL https://raw.githubusercontent.com/JesunAhmadUshno/jesun-code/main/scripts/install.sh | sh. On Windows PowerShell: irm https://raw.githubusercontent.com/JesunAhmadUshno/jesun-code/main/scripts/install.ps1 | iex. Then jesun program.jc runs a file and jesun alone opens the REPL.

What happens when my program has an error?

You get one plain-English sentence with a line number, like Line 3: I expected a value here. Tracebacks do not exist in Jesun.Code. Every failure path in the interpreter is tested to produce a human sentence.

Can it use Python libraries?

Yes. import numpy (or any stdlib or pip package) works through the Python bridge. Inside Jesun.Code you keep speaking Jesun.Code; at the border with Python you use Python's manners: dotted names, parentheses, commas.

How does the AI brain work?

ask ai "write a haiku about compilers" giving poem sends the prompt to the connected mind. You connect one with JESUNCODE_AI_COMMAND, a command that reads a prompt on stdin and writes the answer on stdout. Three providers ship with the installer: Pollinations (free forever, no key), Gemini (free with a Google account), and OpenAI (your own key). Named agents add persona, tools, streaming, and persistent memory.

What is a fleet?

A fleet is a team of agents. fleet panel with researcher and critic opens a block with one ask <member> "question" giving answer per line; the asks run in parallel and the fleet name becomes the answers in ask order. An optional memory file is "crew.json" line gives the fleet shared memory: past answers are prepended to every prompt as The fleet remembers:. If any ask fails, the fleet fails with that ask's plain-English error.

What is jpm?

jpm is the Jesun.Code package manager. use "github.com/user/pkg" installs a package straight from GitHub into ~/.jesun-code/packages/; bring in "pkg" loads it. Three starter packages ship in the repo: time, files, and http.

Does Jesun.Code speak Bangla?

Yes, since v0.5.0. Start a file with use bangla (or a lone বাংলা) and all 67 keywords become Bangla words: দেখাও for show, হয় for is, যদি...তাহলে for if...then. Bengali digits and মন্তব্য comments work too. Same grammar, different tongue.

Is there a VS Code extension?

Yes, in editors/vscode/: syntax highlighting for English and Bangla keywords, snippets, and run-file on Ctrl+Alt+R. The grammar is generated from the interpreter itself, so it can never drift out of sync.

Can Jesun.Code build websites?

Yes, both sides. v1.2.0 shipped jweb and sqlite: routing, sessions, static files, and parameterized queries, all written in Jesun.Code itself. v1.3.0 adds the frontend: the html package (an escaped HTML DSL), the template package ({{ }} placeholders, {% for %} loops, {% if %} conditionals), and the js package (breakout-proof JavaScript strings, script tags, event wiring). See examples/todo_frontend.jc: a full page built from sentences, no Python in the path.

Can Jesun.Code talk to WordPress, React, or PHP?

Yes, since v1.4.0. bring in "wordpress" talks to any WordPress REST API: wp_site with "https://demo.wp-api.org/wp-json" and nothing and nothing then wp_posts with site and 3 gives you shape-checked posts, with plain-English errors and zero tracebacks. bring in "react" builds JSX as text (component, state_hook) and scaffold_app writes a runnable Vite skeleton. bring in "php" emits Laravel routes, controllers, and Blade pages, and php_scaffold writes the project tree. The bridge is bootstrap only: raw transport primitives in, every rule and every error in Jesun.Code itself.

Can Jesun.Code build its own website?

Yes, since v1.5.0, and it does. The sitegen package is a static site generator written in Jesun.Code itself: chrome builders for the head, the nav, and the footer, blog builders for the index and the posts, and machine files for the sitemap, robots.txt, and llms.txt. One driver file and one sitegen_build call rebuild this whole site page-for-page identical, byte for byte, on both interpreters. The page you are reading was built this way.

What is the roadmap?

v1.0.0 shipped self-hosting: the interpreter (jesun.jc) is written in Jesun.Code itself (the Python implementation is the bootstrap only). v1.1.0 shipped native builds: jesun build transpiles the core language to C and compiles real native binaries with no bundled runtime in the output. v1.2.0 shipped jweb and sqlite: a web framework and a database written in Jesun.Code itself, with routing, sessions, static files, parameterized queries, and plain-English errors. v1.3.0 shipped the frontend: the html package (escaped HTML DSL), the template package ({{ }} placeholders, for loops, if conditionals), and the js package (breakout-proof JS strings, script_tag, dom_ready, on_event, js_fetch), all written in Jesun.Code itself with zero bridge. v1.4.0 shipped interop: the wordpress package (any WP REST API, raw urllib primitives in, every rule and error in Jesun.Code), the react package (JSX builders plus a Vite scaffolder), and the php package (Laravel routes, controllers, Blade pages, plus a project scaffolder). The honest framing: the jesun tool itself still ships as a single bundled binary (you never install Python); what changed is that jesun build now produces genuinely native programs. Neither is claimed otherwise.
