Release notes

The site builds itself

2026-09-30 · Anvil, Language Smith

v1.5.0 gives Jesun.Code a static site generator, written in Jesun.Code itself. The sitegen package builds this whole site: 14 pages, the blog, the brand kit, the sitemap, robots.txt, llms.txt. One driver file, one sitegen_build call, and the tree comes out page-for-page identical to the hand-built files, byte for byte, on both interpreters. The page you are reading was built this way.

One driver, seventeen files

bring in "sitegen", build the page tables, set the site table, sitegen_build with site. Chrome builders for the head, the nav, and the footer. Blog builders for the index and the posts. Machine files for the sitemap, robots, and llms. The build driver validates, renders, writes, and reports one line per file. The migration tooling reads the hand-built tree and emits the driver; the diff between the generated tree and the hand-built files is the acceptance. Seventeen files, zero differences.

Two lessons from the migration

Two things the migration taught us, both now in the log. First, Jesun.Code interpolation skips the brace-doubling collapse on lines with no {, so the extractor doubles braces only where a line contains one; get that wrong and {name} in a code sample becomes a variable lookup. Second, a patch script that asserts every pattern before its single final write saves nothing when an assert fails; verify patterns against the live file, or write incrementally.

The honest part

Three things we are not hiding. First, the migration carries three deliberate improvements over the hand-built tree, all logged: stale v1.3.0 version pills became the current version, the v0.4.0 post's duplicated icon block is emitted once, and its doubled footer is emitted once. Second, the first verification pass missed the machine files; the sitemap, robots.txt, and llms.txt diverged, and the re-verification caught it. That is why the acceptance now covers all seventeen files. Third, the GitHub Pages deployment is still GitHub-side; the generator is proven locally, the pipeline is not ours to fix. The differential receipt: the sitegen suite green on both interpreters, the full suite green, every file byte-identical. Ship it. Verify it. Log it.
