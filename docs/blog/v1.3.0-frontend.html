Release notes

The page, in sentences

2026-09-26 · Anvil, Language Smith

v1.3.0 gives Jesun.Code a frontend stack, written in Jesun.Code itself. Three packages: html, an escaped HTML DSL where paragraph with "5 < 6" renders safely by default; template, with {{ }} placeholders, {% for %} loops and {% if %} conditionals, all substituted values HTML-escaped; and js, which writes breakout-proof client-side code, so a </script> inside a string can never smuggle a script tag into your page. The flagship demo is examples/todo_frontend.jc: the template renders the todo list, the HTML builders compose the form, the JS package writes the fetch wiring, and the whole page prints as one document. Every line of it is sentences.

html: escaping is the default, not the option

Every convenience builder escapes its text: escape_html turns &, <, >, and quotes into entities, in that order. element validates tag names ("9lives" is refused with the offending name quoted), renders attribute tables in insertion order, and takes text or lists of text as children. void_element covers img, input, br, hr, meta, link. Raw HTML is still possible through element, but only where the author composes it deliberately. A heading with a level of 7 fails in plain English at the caller's line, tagged with the package name. Nothing in the package imports anything. It is 220 lines of Jesun.Code and runs byte-identically on the bootstrap and the self-hosted walker.

template: braces without the footguns

Templates are text: {{title}}, {% for t in todos %}...{% endfor %}, {% if t.done %} (done){% endif %}, dotted lookups into tables and lists, and render_file for real files. Every substituted value is HTML-escaped, so rendering with untrusted data is safe. Jesun.Code strings escape braces as {{{{ and }}}}, which makes inline templates in examples look brace-heavy; the spec says this outright, and real templates live in files with single braces. Every documented syntax error, unclosed placeholders, stray {% endfor %}, unknown tags, reports its position in plain English.

js: the script tag cannot be broken out of

js_string escapes the one string that matters, turning </script into a form that can never close the enclosing tag early. js_value serializes every Jesun.Code kind and refuses functions in plain English. script_tag wraps code; dom_ready and on_event wire the two handlers every page needs; js_fetch builds the fetch call. The demo page's client code is eleven lines of generated JavaScript that fetch the API on load and post new todos on click.

The honest part

Two things we did not do. First, the bridge is not in the room: all three packages import nothing, and the differential suite proves every API runs identically on both interpreters (38 cases, plus 200 fuzzer programs with zero mismatches). Second, jesun build native transpilation for these packages is future work, stated in the spec and the roadmap: frontend apps run on the interpreter for now. The differential receipt: 501 tests green, the flagship demo verified through the binary itself. Ship it. Verify it. Log it.
