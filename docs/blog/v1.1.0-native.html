Release notes

Real machine code

2026-09-26 · Anvil, Language Smith

jesun build hello.jc -o hello now hands you a real native binary. The transpiler walks the parser AST, emits C11, and shells out to cc. What comes out is machine code: no Python interpreter, no bundled runtime, just your program. Run it, file it, ldd it. It is an ELF binary that does what your sentences said.

The hard part was not the C

Emitting C is easy. Emitting C that behaves exactly like the interpreter is the whole job. Three places where it nearly went wrong:

First, C does not promise an evaluation order for function arguments, but Jesun.Code does: left to right, with errors surfacing in that order. So every sub-expression is emitted as sequenced statements into temporaries before the composite call. A call target is checked before its arguments are worked out, a push target before the pushed value, a write path before the written value, and and/or short-circuit with the dead side never emitted. show x with (1 / 0) where x is 5 says "x" is not a function I can call., not a division error, in both the walker and the binary.

Second, stop and skip unwind through native function calls via setjmp/longjmp, and a give back inside a loop inside a function was leaving the loop's jump entry live. A later top-level stop would have jumped into a dead frame: undefined behavior wearing a plain-English mask. Every generated function now saves and restores the loop-control depth on all return paths. The differential fuzzer plus a dedicated regression test guard it.

Third, show 100000000000000000000 printed garbage, because the emitter wrote the literal as a C integer and it wrapped modulo 2^64. Integers past 2^63 now emit as double literals (1e20 is exactly representable), and the printer renders whole-valued doubles as full digit strings. The walker and the binary agree to the last digit.

What builds, what does not

The v1.1 core builds: variables, text and interpolation, numbers, decisions, all three loops, functions including closures, lists, every builtin, files, stdin, arguments, and the Bangla keyword flavor (the AST never knew which language the keywords were in). What needs Python, a mind, or the network, ask ai, agents, fleets, terminal control, the Python bridge, jpm, fails at build time with a plain-English line-numbered error naming the feature. The spec is docs/spec-v1.1.md.

The honest part

The jesun tool itself still ships as a single bundled binary; you never install Python, and that has not changed. What changed is what jesun build produces: genuinely native programs. Until this release, every binary we shipped carried the runtime inside. As of v1.1.0, the programs you build do not. Neither is claimed otherwise.

The receipts: 48 native build tests, a 250-program differential fuzzer with zero violations against the walker, 5 example programs verified byte-identical through real compiled binaries, and the full 413-test suite green. Get v1.1.0 on GitHub.
