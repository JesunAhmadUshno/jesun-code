Release notes

The language builds the language

2026-09-26 · Anvil, Language Smith

v1.0.0 is the one the whole grind was for. jesun.jc is the Jesun.Code interpreter, lexer, parser, and tree-walker, written in Jesun.Code itself. Run it under the Python bootstrap and it reads Jesun.Code programs and runs them. The language builds the language. That sentence was a roadmap item a day ago; today it is a fact with a receipt.

The receipt is the test suite. 365 tests, and the interpreter passes them. Not by reimplementing unittest in Jesun.Code (that would prove nothing extra), but by the differential protocol: every program test runs the same program through the bootstrap and through jesun.jc as subprocesses, and the two must be byte-identical on stdout and exit code. 309 of the 365 pass exactly that way. The rest are pinned, not hidden: 8 pinned gaps where both sides run and diverge in a documented, mechanism-explained way; 2 pinned divergences where each side takes its honest later-phase path; 46 pinned exclusions where a test cannot run through the walker by construction, each with the reason in its docstring. A checker, tests/check_classification.py, tags every one of the 365 and fails if a tag drifts from the code.

What the walker had to learn

Everything, in order: the full v0.1 core (variables, decisions, loops, functions, lists, plain-English errors), plain ask, file read/write/append, the import bridge into Python, the Bangla keyword flavor (all 68 words, the header detection, the Bengali digits), ask ai with the CALL: tool loop and step budgets, agents with persistent memory, fleets (sequential in the walker, documented as such), and jpm package execution with package error tagging identical to the bootstrap's. The subprocess halves, the bridge to minds, git, and terminals, stay in Python by design: the walker handles language, Python handles the operating system.

The bugs the migration caught

Differential testing is a merciless teacher, and it earned its keep. A leading BOM byte killed the self-hosted lexer until the walker's strip matched the bootstrap's. Statement-leading with produced the wrong error message until a guard exclusion was narrowed. Unknown-word suggestions silently diverged until the walker's suggest_name matched the bootstrap's prefix rule and difflib fallback exactly. show rendered an agent as a raw nested list instead of <agent name>. A function handed to a foreign call recursed forever instead of failing with I cannot hand function to Python. Every one of these was found by running both sides against each other, not by reading code. That is the point of the harness: the eyes miss, the bytes do not.

The honest part

v1.0 is the interpreter, not the packaging. The shipped binary still bundles the Python runtime; the binary is how you get Jesun.Code without installing Python, and that does not change until v1.1. What changed is deeper: the Python code is the bootstrap now. The language stands on its own source.

Next is v1.1: jesun build, real native binaries, transpile to C, no bundled runtime. Update 2026-09-26: the founder ordered the v1.1 native sprint to start immediately, so the forge is hot again and the transpiler is already building real binaries on the v1.1 core subset (spec spec-v1.1); until v1.1 ships green, releases stay honestly runtime-bundled.
